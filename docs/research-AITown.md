# 深度研究报告：AI 小镇（可参与的 AI 居民小镇 Web 应用）

> **来源标注说明**：带 ✅ 的事实来自联网检索（附 URL 与访问日期 2026-08-14）；带 ⚠️ 的为 "Unverified — model knowledge"（模型知识，未验证）；所有成本数字均为**假设性估算**，已标注假设条件。

---

## 1. Project name

**AI 小镇（AI Town，暂定名）** —— 一个 2D 像素风的 Web 应用：AI 居民在小镇里自主生活、社交，而你以居民身份走进小镇、与他们互动并影响小镇的发展。

## 2. Core concept

**是什么**：受斯坦福 Smallville（生成式智能体）启发的可参与式 AI 小镇模拟。

**解决的问题**：
- 现有 AI 陪伴产品（Character.AI 类）是"一对一聊天"，缺乏世界感和涌现叙事
- Smallville 类的学术 demo 只能旁观，无法参与
- 本项目的定位是两者的交集：**一个有自主生活的世界 + 你能走进去成为故事的一部分**

**为什么是现在**：
- Smallville 论文 ✅（arXiv:2304.03442，2023-04 提交，访问日期 2026-08-14）验证了"记忆流 + 反思 + 规划"架构能产生可信的个体行为和涌现社会行为（25 个智能体自发传播情人节派对邀请、互相约会、准时赴约）
- 开源生态已成熟：a16z 的 AI Town ✅（MIT 协议、10.3k stars、2026 年 6 月仍在维护，<https://github.com/a16z-infra/ai-town>，访问日期 2026-08-14）证明这类项目可以产品化
- LLM 成本大幅下降（低价国内大模型 API 已普及），让个人开发者跑多智能体小镇成为可能；本项目 LLM 选用 **MiniMax API**（2026-08-14 决策变更，原方案 DeepSeek，见 4.1 与第 6 节）

## 3. Target users

| 阶段 | 用户 | 需求 | 痛点 |
|------|------|------|------|
| 现在（MVP） | **开发者本人** | 一个能玩、有趣、有陪伴感的小镇 | 现有产品要么只能旁观、要么只是聊天框 |
| 验证期 | 朋友 / 独立游戏&AI 爱好者 | 新奇体验、可分享的 AI 涌现故事 | 同类体验稀缺 |
| 远期 | AI 陪伴+模拟经营交叉用户（星露谷玩家 × Character.AI 用户的交集）⚠️ | 慢节奏、有情感联结的虚拟世界 | —— |

## 4. Technical decisions（技术选型建议）

### 4.1 推荐技术栈

| 层 | 推荐 | 替代方案 | 理由 |
|---|------|---------|------|
| 前端渲染 | **Phaser v4** ✅（官网确认 v4 已发布且开源，且官方推出了 Phaser Game Agent / MCP 辅助 AI 编程，<https://phaser.io>，访问日期 2026-08-14） | PixiJS v8 ✅（WebGPU/WebGL 2D 渲染器，开源，<https://pixijs.com>，访问日期 2026-08-14） | Phaser 是完整游戏框架（瓦片地图、相机、输入、动画开箱即用），更适合 1 个月 MVP |
| 前端语言 | TypeScript + Vite | JavaScript | TS 类型提示能显著降低 AI 辅助编程的出错率 ⚠️ |
| 后端 | **FastAPI（Python）** | Node.js/Express | 发挥已有 Python 基础；AI 居民逻辑（提示词、记忆管理）用 Python 写起来快 ⚠️ |
| 实时通信 | WebSocket（FastAPI 原生支持） | Server-Sent Events | 小镇状态需要持续推送到前端 ⚠️ |
| 数据库 | **SQLite**（本地零成本） | PostgreSQL（部署期再说） | MVP 阶段单文件数据库足够 ⚠️ |
| 记忆检索 | MVP 用"时间近因 + 重要性评分 + 关键词匹配"（论文检索三要素的简化版）；暂不上向量数据库 | 本地嵌入模型（如 bge-small）做向量检索 ⚠️ | MiniMax 当前不提供 embedding 接口 ✅（2026-08-14 查官方文档索引，语言模型仅对话生成类），向量方案仍需本地模型，MVP 可跳过 |
| LLM | **MiniMax API**（2026-08-14 决策变更，原方案 DeepSeek v4-flash/pro）：轻量层 **MiniMax-M2.7**（对话/计划/感知），旗舰层 **MiniMax-M3**（反思等高质量任务）✅ | M2.7-highspeed（效果不变、更快、2 倍价，延迟敏感时可选） | 用户指定；国内可直连；模型与定价已核实（见 6.1）；兼容 OpenAI / Anthropic SDK、支持 Prompt 缓存 ✅ |

### 4.2 Phaser vs PixiJS 对比

| 维度 | Phaser v4 | PixiJS v8 |
|------|-----------|-----------|
| 定位 | 完整游戏框架 | 纯渲染引擎 |
| 瓦片地图 | ✅ 内置 | 需自己写或找库 |
| 学习曲线 | 概念多但教程丰富 | API 简洁但要自己搭游戏逻辑 |
| 性能 | 好 | 官方自称"最快的 2D WebGPU/WebGL 渲染器" ✅ |
| AI 辅助开发 | 官方 Game Agent + MCP ✅ | 官方提供 llms 文档页 ✅ |
| 适合 MVP 的程度 | ★★★★★（MVP 要的就是少造轮子） | ★★★（更适合做定制化视觉） |

**结论：MVP 用 Phaser v4；若后期性能或定制需求出现再考虑 PixiJS。**

### 4.3 要不要直接 fork a16z AI Town？

| 方案 | 优点 | 缺点 |
|------|------|------|
| Fork a16z ai-town ✅（MIT 协议允许） | 架构现成、有完整实现参考 | 深度绑定 Convex 后端平台（Convex 免费额度有限 ⚠️）、TypeScript 全栈带来新学习负担、代码量大（1,143 commits）改起来不一定比写快 |
| **自己写 + 读它的代码找灵感**（推荐） | 完全符合现有技能栈和免费约束 | 开发量稍大，但 1 个月 MVP 目标下功能本就要砍 |

**结论：把 a16z ai-town 当"参考实现"读，自己用 Phaser + FastAPI 写精简版。** 同理，Smallville 官方代码仓库（joonspk-research/generative_agents，⚠️ 模型知识：Django 后端 + Phaser 前端）也值得读——它恰好证明了"Python 后端 + Phaser 前端"这条路线是原作者验证过的。

> ⚠️ 本节除 a16z ai-town 外均为 "Unverified — model knowledge"（竞品页面抓取超时未能验证），建议对重点结论自行复核。

| 产品 | 类型 | 核心体验 | 用户喜欢 | 用户不满 | 与本项目的差异 |
|------|------|---------|---------|---------|-----------|
| Character.AI ⚠️ | 1对1 AI 角色聊天 | 与海量 UGC 角色对话 | 角色丰富、对话质量好 | 无世界感、长期记忆弱、内容审核争议 | 本项目是"世界"，它是"聊天框" |
| Replika ⚠️ | AI 伴侣 | 深度 1v1 情感陪伴、虚拟形象 | 情感联结强 | 订阅贵、单一关系 | 本项目是多角色社会关系网 |

| 猫箱（字节）⚠️ | AI 剧情聊天（国内） | 场景化 AI 互动小说 | 剧情感强 | 本质是分支叙事 | 本项目的故事是涌现的，不是写好的 |

| a16z AI Town ✅ | 开源自部署 demo | 2D 小镇 + AI 聊天 | 开源可定制 | 需要自部署、非消费级产品 | 本项目目标是开箱即玩的 Web 产品 |

**可切入的空白**：市面上几乎没有"**消费级、可参与、有持续运转世界**"的 AI 小镇产品。差异化关键词：**世界在你离开时也活着、居民记得你做过的事、故事是涌现而非剧本**。

## 6. Budget/timeline

### 6.1 MiniMax API 定价 ✅（<https://platform.minimaxi.com/docs/guides/pricing-paygo>，访问日期 2026-08-14）

| 模型 | 输入（元/百万 tokens） | 输出（元/百万 tokens） | 缓存读取 | 缓存写入 |
|------|----------------|------------------|------|------|
| **MiniMax-M3**（旗舰，1M 上下文；≤512k 输入） | 2.10（永久五折后，原价 4.20） | 8.40（原价 16.80） | 0.42 | 未单列 |
| **MiniMax-M2.7**（轻量主力） | 2.10 | 8.40 | 0.42 | 2.625 |
| **MiniMax-M2.7-highspeed**（效果不变、更快） | 4.20 | 16.80 | 0.42 | 2.625 |

注：优先服务（`service_tier=priority`）按标准价 1.5 倍计费，响应更快；M3 输入 > 512k tokens 时价格翻倍（本项目用不到）；Token 换算（官方估算）：1600 中文字符 ≈ 1000 tokens。

**已核实要点：**
- ✅ **支持 Prompt 缓存**：缓存读取价 = 输入价的 1/5（0.42 vs 2.10），人设前缀固定策略确认有效；另有 Anthropic 兼容的"主动缓存"模式
- ✅ **SDK 兼容**：同时提供 OpenAI 兼容（Chat Completions / Responses）与 Anthropic 兼容（Messages）接口，Python 端可用 `openai` 或 `anthropic` SDK 直接接入
- ✅ **无峰谷计价**：仅标准/优先两档；原 DeepSeek 的"谷时跑重任务"策略不适用
- ✅ **无 embedding 接口**：官方文档索引中语言模型仅对话生成类，向量检索仍需本地模型

~~原 DeepSeek v4 定价（已作废，仅作历史参考）~~：flash 输入 $0.0028/M（缓存命中）/ $0.14/M（未命中）、输出 $0.28/M；pro 输入 $0.0036/M（命中）/ $0.435/M（未命中）、输出 $0.87/M ✅（<https://api-docs.deepseek.com/quick_start/pricing>，访问日期 2026-08-14）；官方曾公告 2026-08-16 起切换峰谷定价。以上均不再适用于本项目。

### 6.2 月度成本估算（假设性估算，非实测）

**假设**：10 个居民；事件驱动循环（居民无事不做不调用）；每个居民每游戏日约 40 次调用；单次平均 3K token 输入 + 300 token 输出；每天玩 2 个游戏日。

- 每游戏日：10 × 40 = 400 次调用 ≈ 1.2M 输入 + 0.12M 输出（用量估算与 provider 无关，仍成立）
- 按 M2.7 已核实单价（输入 ¥2.1/M、输出 ¥8.4/M、缓存读取 ¥0.42/M）：
  - 无缓存命中：1.2×2.1 + 0.12×8.4 ≈ **¥3.53/游戏日**，每月 60 游戏日 ≈ **¥212/月**
  - 50% 输入缓存命中：≈ **¥2.52/游戏日** ≈ **¥151/月**
  - 80% 输入缓存命中：≈ **¥1.92/游戏日** ≈ **¥115/月**
- ⚠️ **成本压力大于原 DeepSeek 方案**：PRD 目标 $0.30/游戏日（≈¥2.1）需 ~70%+ 输入缓存命中率才能达标——人设前缀逐字固定 + Prompt 缓存是达标关键；若实测超标，优先下调"每居民 40 次调用/游戏日"的用量假设（事件驱动保底线）
- 开发调试期用量远低于运行期估算，**预计每月 ¥20–60**（假设性估算）

**控成本手段**（按见效排序）：
1. **事件驱动 > 时钟驱动**——居民没事干时不调用 LLM，这是最大的节省（论文的逐 tick 驱动方式对 MVP 是浪费）
2. **复用缓存**——居民人设等固定前缀放 prompt 开头并逐字固定；MiniMax Prompt 缓存已核实 ✅，缓存读取价是输入价的 1/5，这是达标成本目标的关键杠杆
3. **记忆摘要压缩**——老记忆定期压缩成摘要，控制 prompt 长度
4. **轻量模型干杂活，旗舰模型只做"反思"**等高质量任务（M2.7 / M3 标准价相同，分层的意义在稳定性与能力而非价格）
5. ~~谷时跑重任务~~（原 DeepSeek 峰谷定价策略；MiniMax 无峰谷计价 ✅，改为：非延迟敏感任务用标准档即可，不要开 priority）

### 6.4 时间线

**4 周 MVP 路线图**（假设每周投入 15–20 小时）：

| 周 | 目标 | 产出 | 学习里程碑 |
|---|------|------|-----------|
| W1 | 跑通骨架 | Phaser 加载像素地图、玩家角色可走动；FastAPI 起服务、前后端 WebSocket 连通；MiniMax 第一次调用成功（验证 M2.7/M3 分层与延迟；定价已核实见 6.1） | Phaser 场景/精灵/瓦片地图；FastAPI + WebSocket |
| W2 | 居民会"过日子" | 居民数据模型（人设、位置、状态）；感知→检索→计划→行动的最小循环；记忆流存 SQLite | 提示词工程；游戏主循环与 AI 循环解耦 |
| W3 | 居民会社交、你能参与 | 居民相遇触发对话；玩家走近居民可聊天；对话写入双方记忆 | 对话状态机；多智能体对话调度 |
| W4 | 成为"游戏" | 昼夜循环与作息；简化反思（每日总结）；存档/读档；UI 打磨、试玩修 bug | 整体联调与成本实测 |

**MVP 功能优先级矩阵**：

| 必须有（Must） | 应该有（Should） | 暂缓（Later） |
|---------------|-----------------|--------------|
| 像素小镇地图 + 玩家移动 | 昼夜循环/居民作息 | 向量记忆检索 |
| 5–10 个有人设的居民 | 简化版每日反思 | 居民间关系系统（好感度） |
| 居民自主移动 + 日常行为 | 居民主动发起话题 | 建造/经营玩法 |
| 玩家与居民对话（有记忆） | 事件日志流（小镇播报） | 本地模型迁移 |
| 记忆流（SQLite） | | 多人同镇 |
| 存档/读档 | | 部署上线公开 |

**论文里 MVP 可以砍掉的东西** ✅+推断：25 个居民（5–10 个足够出效果）、完整的递归式反思树（先做每日一次总结）、精细的空间寻路（像素小镇可用简单网格寻路）、论文级评估实验。

## 7. 交付物汇总

- ✅ **Feature Matrix**：见 6.4 优先级矩阵
- ✅ **Tech Stack**：Phaser v4 + TypeScript/Vite + FastAPI + SQLite + MiniMax API（M2.7 轻量层 + M3 旗舰层 ✅，见 4.1/6.1）
- ✅ **AI 居民架构**（简化 Smallville）：

```
感知（周边事件/玩家动作）
   ↓
记忆检索（近因 + 重要性 + 关键词，SQLite）
   ↓
计划（早晨生成当日计划；事件触发时局部重规划）
   ↓
行动（移动 / 对话 / 互动）→ 结果写入记忆流
   ↓
反思（每日一次：把当天记忆压缩成高层认知，如"玩家喜欢来面包店"）
```

- ✅ **AI 工具指南**：编码用 AI IDE（如 CatPaw/Cursor）+ Phaser 官方 Game Agent/MCP ✅；像素美术用 AI 文生图工具生成 sprite 后手工微调 ⚠️；文案/人设用 LLM 网页版（MiniMax 等）免费头脑风暴
- ✅ **学习资源（免费优先）**：Phaser 官方教程与示例 ✅（<https://phaser.io/learn>）、FastAPI 官方文档、Smallville 论文 ✅（<https://arxiv.org/abs/2304.03442>）、a16z ai-town 源码 ✅（<https://github.com/a16z-infra/ai-town>）
- ✅ **Budget**：MVP 期总计 ≈ **¥0 固定成本 + MiniMax API 浮动成本**（按已核实单价估算：运行期 ¥115–212/月、开发期 ¥20–60/月，均为假设性估算，见 6.2）
