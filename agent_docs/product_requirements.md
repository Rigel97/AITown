# Product Requirements

> Fill this in from the PRD (`docs/PRD-*.md`). This is the agent's quick-reference version — keep it short and current.

## Product Summary
- **Product:** AI 小镇（AI Town，暂定名）
- **One-liner:** AI 居民自主生活、社交的 2D 像素小镇，玩家以居民身份走进小镇，与居民自由对话并影响小镇发展。
- **Target users:** 开发者本人（Level C：Python 有基础、正在学全栈 + AI 开发）；验证期为朋友 / 独立游戏 & AI 爱好者。远期用户（星露谷玩家 × Character.AI 用户交集）不在 MVP 考虑范围。

## User Stories
- As a 玩家，I want 打开页面即进入小镇俯瞰视图（无注册无引导）so that 立刻获得"世界感"。
- As a 玩家，I want 用方向键在小镇行走、走近居民即可自由文本对话 so that 我是"参与"小镇而非旁观。
- As a 玩家，I want 居民记得我做过的事并在后续对话中提起 so that 获得长期陪伴感与情感联结。
- As a 玩家，I want 离开时小镇继续运转、回来后能通过事件日志看到变化 so that 我想明天再回来看看。
- As a 开发者，I want 架构清晰、关键模块有设计解释 so that 我能向朋友演示并讲清多智能体架构。

## Feature List (MoSCoW)

### Must Have
- [ ] 像素小镇地图 + 玩家移动（Phaser 瓦片地图，方向键移动含碰撞，4–5 个可辨识功能区）
- [ ] AI 居民（5–10 个，姓名/职业/性格/背景故事独立人设，写入 prompt 固定前缀）
- [ ] 居民自主行为（感知→记忆检索→计划→行动，事件驱动，无事不调 LLM）
- [ ] 玩家与居民自由文本对话（有记忆：检索相关记忆注入 prompt，对话写入双方记忆流，响应 < 5 秒）
- [ ] 记忆流（SQLite：时间戳 + 重要性评分；近因+重要性+关键词 Top-K 检索；老记忆摘要压缩）
- [ ] 每日简化反思（游戏日结束压缩成 1–2 条高层认知写回记忆流，性格可随事件演变）
- [ ] 存档/读档（小镇完整状态可保存与恢复，重开后世界连续）

### Should Have
- [ ] LLM 调用失败/超时的降级路径（符合人设的托词，绝不暴露原始报错）
- [ ] 出戏防护（prompt 指令"永不承认自己是 AI"，发现出戏回复记录日志并迭代 prompt）
- [ ] 小镇事件日志流 UI（按时间倒序播报，让涌现可见）

### Could Have
- [ ] 昼夜循环 + 居民作息（白天活动晚上睡觉）
- [ ] 居民主动发起话题（"上次你说的那件事……"）

### Won't Have (this version)
- 向量记忆检索（V2，MiniMax 无 embedding 接口，届时走本地模型）
- 居民间好感度/关系系统（V2，先用记忆与反思近似）
- 建造/经营玩法、多人同镇（V2+）
- 公网部署、用户系统/付费/增长机制（商业化阶段）
- 移动端适配（视反馈决定）
- 论文级反思树 / 25 个居民 / 评估实验（视效果决定）

## Success Metrics
- **北极星：** 自己连续 7 天主动打开玩（2026-09-28 前；自我记录 + 本地游玩日志）
- **作品集验证：** 能给 3 个朋友完整演示并讲清架构（上线后 2 周内，现场或录屏）
- 3 个月内 5–10 个朋友试玩，收到 ≥ 3 条具体反馈
- 单次游戏日 API 成本 ≤ $0.30（≈¥2.1，需 ~70%+ 缓存命中率，W4 实测校准）
- 每周至少 1 个"没想到居民会这样"的涌现时刻
- 性能：页面加载 < 3 秒、渲染流畅 60fps、对话响应 < 5 秒

## Out of Scope
- 见上方 Won't Have 全表——构建中途即使被临时提起也不得实现；核心红线：不公网部署、不做移动端、不上向量库、不做多人。保持 MVP 聚焦，先把"活着的小镇 + 可参与"验证扎实。
